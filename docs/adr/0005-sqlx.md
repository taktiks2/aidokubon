# DB へのアクセスに ORM ではなく sqlx を使い、SQL を直接書く

PostgreSQL の機能を何の制限もなく使いつつ、`query!` マクロで SQL と Rust の型の対応をコンパイル時に検査したい。そのため sqlx を使う。生の SQL は、AI が書いたものを人がレビューしやすく、エラーも読みやすい。CI とオフラインでのビルドでは、`cargo sqlx prepare` で作った検査結果のキャッシュを使う。

## Considered Options

| 案 | 見送った理由 |
|---|---|
| Diesel | DSL で書いても型の検査は効くが、DSL が対応していない PostgreSQL の機能は生の SQL になり、検査が外れる。型エラーが長く、AI が修正を繰り返すときの足かせになる。本体は同期で、非同期にするには別のクレートが要る |
| SeaORM | コンパイル時の検査がほぼなく、実行時に失敗する |
| Clorinde（旧 cornucopia） | 方針は近いが、マイグレーションに別のツールが要り、利用者も少ない |

## Consequences

- 動的なクエリ（検索の絞り込みなど）は `QueryBuilder` を使わず、条件が固定の SQL（`WHERE ($1::text IS NULL OR ...)`）か、パターンごとの別々のクエリで書く。検査が効く範囲から外さないため。
