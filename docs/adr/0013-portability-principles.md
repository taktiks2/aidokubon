# クラウドや DB を移せるように、4 つの約束を守る

将来は一般公開し、DB が大きくなればホスティングの移行もありうる。クラウドの選択（ADR-0011）を戻せる判断にしておくため、次の 4 つを守る。

1. API はステートレスなコンテナにし、状態は PostgreSQL にだけ持たせる。
2. 標準の PostgreSQL の機能だけを使い、Neon 固有の機能に依存しない（`pg_dump` や論理レプリケーションで、どこへでも移せるようにする）。
3. 認証は、同じセッションの ID を Cookie（Web）と `Authorization: Bearer`（スマホのアプリ）の両方で受け取れるようにする。スマホのアプリに展開するときの最大の障害を、先に取り除いておく。
4. インフラはすべて IaC（ADR-0012）で書き、IaC で管理できないものは手順を残す。

これらの約束は、コードを読んだだけでは「なぜ、わざわざこうしているのか」が分からない。そのため、ADR として残す。
