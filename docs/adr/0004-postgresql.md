# DB に PostgreSQL を使う

このプロジェクトの目的の 1 つは、DB 設計の歯ごたえである。ドメインの規則を、アプリのコードではなく DB の制約として表現したい。たとえば「返されていない貸出は、1 つの蔵書に 1 つまで」を部分ユニークインデックスで表す。PostgreSQL は、部分ユニークインデックス、CHECK 制約、enum 型、排他制約（将来の予約機能）、RLS（グループ単位でのデータの分離）、jsonb（楽天 API の生レスポンスのキャッシュ）がそろっていて、この用途に最も幅が広い。sqlx の型の検査も、PostgreSQL で最も正確に効く。

## Considered Options

| 案 | 見送った理由 |
|---|---|
| MySQL | 部分インデックス、排他制約、RLS がない。無料で使えるマネージドのサービスも少ない |
| SQLite（libSQL / Turso を含む） | 運用は軽いが、型が緩く、DB 側で守れる制約が少ない。「DB に守らせる」方針と逆向き |
