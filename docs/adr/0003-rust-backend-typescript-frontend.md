# バックエンドを Rust、フロントエンドを TypeScript にする

AI 駆動で開発するので、コンパイラを AI の出力を検査するハーネスとして使いたい。そのためにバックエンドを Rust にする。状態を enum にすると、`match` の網羅性の検査で、状態を追加したときの対応漏れがすべてコンパイルエラーになる。sqlx を使えば、SQL をコンパイル時に DB のスキーマに対して検査できる。axum の extractor を使えば、「メンバーであることを確認済み」といった権限を型で表せる。カメラやバーコードの読み取りはブラウザで行うので、フロントエンドは TypeScript にする。実行速度は、この規模では選んだ理由にならない。

## Considered Options

| 案 | 見送った理由 |
|---|---|
| TypeScript で統一する（Next.js など） | 言語が 1 つで済むが、DB の層と状態遷移の検査が Rust よりも弱い |

## Consequences

- 言語の境界で型が途切れないように、OpenAPI で型の連鎖をつなぐ（ADR-0009）。
- ビルドが遅いので、AI の修正ループは `cargo check` を中心に回す。
- TypeScript の Better Auth のような、全部入りの認証ライブラリは使えない（ADR-0010）。
